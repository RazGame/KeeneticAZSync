# Безопасность

AWG Sync предназначен для владельца доверенных VPN-панелей и роутеров. Это административный инструмент с правом изменять устройства, а не многопользовательский сервис с разграничением ролей.

## Развёртывание

- Без учётных данных разрешён только локальный loopback. Для сетевого bind обязательны `BASIC_AUTH_USER` и `BASIC_AUTH_PASS`; сочетание `admin/admin` запрещено.
- Внешний доступ — через HTTPS или SSH-туннель. Сам Node.js обслуживает HTTP; TLS завершает внешний прокси.
- Браузер получает непрозрачную HttpOnly/SameSite-сессию (Secure при HTTPS-входе), срок до 12 часов. Выход отзывает её; рестарт сбрасывает сессии и планы. Basic Auth для API допустим только через защищённое соединение или loopback.
- YAML содержит пароли устройств. Ограничьте каталог `0700`, файл `0600`. Экспорт YAML также содержит секреты; для переносимых копий используйте зашифрованный экспорт.
- Проверка сертификатов включена. Исключение `insecure` разрешает недоверенный TLS отдельно для выбранной панели/роутера.
- Docker-образ работает non-root, без capabilities, с read-only rootfs и writable каталогом конфигурации. Docker socket приложению не требуется.
- Запускайте один процесс с записью в один набор устройств; блокировки не распределённые. При применении настройки/связность VPN могут измениться.

## Границы защиты

Администратор может задавать внутренние адреса панелей и роутеров. Это нужно для LAN и Docker-сетей, но не заменяет сетевую SSRF-изоляцию для недоверенных пользователей. Доверяйте источникам VPN-профилей. Root, администратор Docker или захваченный процесс приложения могут прочитать необходимые для работы секреты.

Проверка кода и целевых сценариев описана в [SECURITY-AUDIT.md](SECURITY-AUDIT.md); она не является обещанием отсутствия всех уязвимостей.

## Сообщить о проблеме

Для уязвимости используйте приватное сообщение владельцу репозитория или GitHub **Security → Report a vulnerability**, если владелец включил private vulnerability reporting. Не публикуйте конфиги, профили VPN, ключи, cookies и пароли в Issues. Если приватного канала ещё нет, в публичном обращении сначала запросите его, не раскрывая детали эксплуатации и секреты.

В обычном отчёте об ошибке полезны версия/commit приложения, версия прошивки/панели, способ запуска и очищенное описание шагов. Полный вывод `docker compose config`, `.env`, YAML и экспорты к сообщению не прикладывайте.
