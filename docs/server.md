# Установка на отдельный сервер

[← На главную](../README.md) · [Установка рядом с AntiZapret](antizapret.md)

После установки AWG Sync будет работать на сервере постоянно. Вы сможете открывать его со своего компьютера, даже когда дома приложение не запущено.

**Если на этом сервере уже работает AntiZapret, перейдите к [инструкции для AZ](antizapret.md).** Она использует его готовый HTTPS-доступ.

Если AWG Sync уже установлен и его нужно только обновить, переходите к [обновлению](#как-обновить).

## Что понадобится

- Linux-сервер, к которому у вас есть доступ по SSH.
- Установленные Git, Docker и Docker Compose v2. Docker устанавливается по [инструкции для вашей ОС](https://docs.docker.com/engine/install/).
- Адреса и пароли VPN-панелей и роутеров, которые вы хотите подключить.

Доступ к админке можно организовать двумя способами. **SSH-туннель** подходит для личного использования и не требует домена. **HTTPS-домен** удобнее, если хотите открывать панель обычной ссылкой, в том числе с телефона. Оба варианта описаны ниже; выполняйте только выбранный.

## Шаг 1. Подключитесь к серверу

Откройте терминал **на своём компьютере**. Подставьте имя пользователя и IP своего сервера:

```bash
ssh user@SERVER_IP
```

После входа следующие команды выполняйте **на сервере**.

Проверьте, что необходимые программы установлены:

```bash
git --version
docker --version
docker compose version
```

Все три команды должны вывести номера версий. Если какая-то не найдена, сначала установите соответствующую программу.

## Шаг 2. Клонируйте репозиторий

Клонируйте репозиторий в папку `/opt/awg-sync`:

```bash
sudo mkdir -p /opt/awg-sync
sudo chown "$(id -u):$(id -g)" /opt/awg-sync
git clone https://github.com/RazGame/KeeneticAZSync.git /opt/awg-sync
cd /opt/awg-sync
```

Файлы проекта теперь находятся в `/opt/awg-sync`. Дальше выполняйте команды из этой папки, если не указано другое.

## Шаг 3. Придумайте логин и пароль

Создайте файл настроек запуска и откройте его:

```bash
cp .env.example .env
nano .env
```

Заполните строки:

```dotenv
BASIC_AUTH_USER=admin
BASIC_AUTH_PASS='ПРИДУМАЙТЕ_СВОЙ_ПАРОЛЬ'
```

Вместо текста `ПРИДУМАЙТЕ_СВОЙ_ПАРОЛЬ` укажите собственный длинный пароль. Одинарные кавычки можно оставить. Это пароль **самой AWG Sync**; доступы к роутерам и VPN-панелям вы введёте позже через браузер.

В редакторе nano сохраните файл: **Ctrl+O → Enter**, затем выйдите: **Ctrl+X**.

Ограничьте доступ к этому файлу и создайте папку для настроек приложения:

```bash
chmod 600 .env
sudo install -d -m 700 -o 1000 -g 1000 config
```

Эти команды нужны, чтобы приложение могло сохранять настройки, а другие пользователи сервера не читали пароли.

## Шаг 4. Выберите способ доступа и запустите

### Вариант A. Через SSH-туннель, без домена

**На сервере**, в `/opt/awg-sync`:

```bash
docker compose config --quiet
docker compose up -d --build
docker compose ps
```

Если первая команда ничего не вывела — настройки прошли проверку. Дождитесь сборки и запуска; в состоянии контейнера должен появиться `healthy`.

Теперь откройте **второе окно терминала на своём компьютере** и выполните, подставив пользователя и IP сервера:

```bash
ssh -N -L 8787:127.0.0.1:8787 user@SERVER_IP
```

После ввода пароля окно может ничего не показывать — это нормально. Оставьте его открытым и перейдите в браузере на **http://127.0.0.1:8787**.

Соединение до сервера проходит через SSH. Когда закроете туннель, панель перестанет открываться на компьютере, но приложение продолжит работать на сервере.

### Вариант B. По HTTPS-домену

Пример ниже использует `sync.example.com`. Замените его своим доменом.

У регистратора домена создайте DNS-запись, направляющую домен на IP сервера. На сервере и в настройках хостинга должны быть доступны порты **80 и 443**. Если их уже занимает другой сайт или прокси, смотрите пояснение ниже.

**На сервере**, в `/opt/awg-sync`, откройте `.env`:

```bash
nano .env
```

Укажите свой домен в строке:

```dotenv
AWG_SYNC_DOMAIN=sync.example.com
```

Сохраните файл и запустите приложение вместе с HTTPS-прокси:

```bash
docker compose -f docker-compose.yml -f deploy/compose.https.yml config --quiet
docker compose -f docker-compose.yml -f deploy/compose.https.yml up -d --build
docker compose -f docker-compose.yml -f deploy/compose.https.yml ps
```

Дождитесь запуска и откройте **https://sync.example.com**, подставив свой домен. Прокси Caddy сам получает и обновляет сертификат, если DNS и доступ к портам настроены правильно.

<details>
<summary>Если на сервере уже есть свой HTTPS-прокси</summary>

Второй Caddy запускать не нужно. Запустите AWG Sync командами из варианта A и добавьте маршрут в существующий прокси.

Если прокси работает на самом сервере, направьте его на `http://127.0.0.1:8787`. Если он работает в общей Docker-сети — на `http://awg-sync:8787`.

Не открывайте порт HTTP приложения в интернет. Для сервера с AntiZapret используйте [его готовую схему HTTPS](antizapret.md).

Подробнее о Caddy: [официальная инструкция](https://caddyserver.com/docs/quick-starts/reverse-proxy).

</details>

## Шаг 5. Войдите и добавьте устройства

Введите логин и пароль из `.env`. Затем пройдите [первую настройку](../README.md#первая-настройка): серверы → роутеры → подключения.

**Домашний адрес `192.168.1.1` обычно недоступен с VPS.** Для управления домашним роутером укажите его облачный URL KeenDNS / CrazeDNS или адрес своей управляющей сети, связанной с VPS.

Пароли VPN-панелей и роутеров вводятся отдельно во вкладке «Доступы».

## Как обновить

Сначала в AWG Sync откройте **«Конфигурация»** и скачайте зашифрованную резервную копию.

На сервере:

```bash
cd /opt/awg-sync
docker tag awg-sync:latest awg-sync:previous
git pull --ff-only
docker compose build awg-sync
docker compose up -d --no-deps awg-sync
```

Команда `docker tag` сохраняет текущую версию для возможного возврата. Затем скачиваются новые файлы, собирается и перезапускается только AWG Sync.

Если используете HTTPS-вариант, в командах `docker compose` указывайте оба файла: `docker compose -f docker-compose.yml -f deploy/compose.https.yml`. Сам Caddy при обычном обновлении приложения пересоздавать не требуется.

После обновления откройте панель и войдите заново.

<details>
<summary>Как вернуться к предыдущей версии</summary>

Если до обновления выполнили команду `docker tag`, можно вернуть сохранённый образ:

```bash
docker tag awg-sync:previous awg-sync:latest
docker compose up -d --no-deps --no-build awg-sync
```

Для HTTPS-варианта добавьте те же два `-f`, что использовали при запуске.

Это возврат версии приложения. Для восстановления его настроек используйте резервную копию из раздела «Конфигурация»; настройки роутеров применяются отдельно.

</details>

## Если панель не открывается

Команды ниже выполняются на сервере из `/opt/awg-sync`. Для HTTPS-варианта добавляйте оба файла `-f`, как при запуске.

```bash
docker compose ps
docker compose logs --tail=100 awg-sync
```

| Что случилось | Что проверить |
| --- | --- |
| В состоянии долго остаётся `starting` или контейнер перезапускается | Посмотрите последние сообщения командой `logs`. |
| `EACCES`, нельзя сохранить настройки | Убедитесь, что выполнили команду создания папки `config` на шаге 3. |
| Не открывается HTTPS | Домен должен указывать на сервер, порты 80/443 должны быть доступны, а другой процесс не должен их занимать. Сообщения прокси: `docker compose -f docker-compose.yml -f deploy/compose.https.yml logs --tail=100 caddy`. |
| Не открывается локальный адрес через SSH | Проверьте, что туннель из варианта A открыт в отдельном окне на вашем компьютере. |
| Панель работает, но не видит роутер | Проверьте доступность его адреса именно с сервера. |

<details>
<summary>Где сохраняются данные</summary>

- `.env` — логин и пароль входа в AWG Sync.
- `config/config.yaml` — доступы к VPN-панелям и роутерам, созданные связи и порядок карточек.
- Данные сертификатов отдельного Caddy — в Docker volumes `caddy_data` и `caddy_config`.

Не удаляйте папку `config` при обновлении. Приложение работает в контейнере от пользователя с номером 1000. Для записи нужен весь каталог `/app/config`, поэтому в шаблоне монтируется папка, а не отдельный файл YAML.

Полный вывод `docker compose config` может содержать пароли. Для обычной проверки используйте `config --quiet` и не отправляйте файлы настроек в публичные обсуждения.

</details>
