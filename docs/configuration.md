# Где хранятся настройки и что означают поля

[← На главную](../README.md)

Обычно редактировать файлы вручную не нужно: добавляйте серверы, роутеры и подключения через браузер. Приложение само сохранит их в `config.yaml`.

Эта страница пригодится, если вы переносите установку, ищете файл для резервной копии или хотите настроить всё вручную.

## Где искать файл настроек

| Как запущено приложение | Где лежит файл |
| --- | --- |
| Через Node.js на компьютере | В папке `node/config.yaml` проекта. |
| Через отдельный Docker Compose | В папке `config/config.yaml` проекта. |
| Вместе с AZ по нашей инструкции | В папке AZ: `config/awg-sync/config.yaml`. |
| С явно указанным путём | По пути из `--config` или `CONFIG_PATH`. |

При первом запуске приложение создаёт пустой файл. После сохранения настроек через браузер он заполняется.

**В этом файле есть пароли VPN-панелей и роутеров.** Для переноса через интерфейс удобнее использовать зашифрованную копию из раздела «Конфигурация».

## Какие пароли где задаются

| Что нужно открыть | Где задаются логин и пароль |
| --- | --- |
| Саму AWG Sync в Docker | В `.env`; для установки с AZ — в `.env.awg-sync`. |
| WG-Easy или OpenVPN UI | В разделе «Доступы → Серверы». |
| Управление роутером | В разделе «Доступы → Роутеры». |

Это разные учётные данные. Пароль входа в AWG Sync автоматически не становится паролем серверов или роутеров.

## Как устроен config.yaml

В файле четыре основных раздела:

| Раздел | Что в нём находится |
| --- | --- |
| `servers` | VPN-серверы и доступы к их панелям. |
| `routers` | Роутеры, их адреса и доступы. |
| `mappings` | Связи между клиентами в панелях и интерфейсами роутеров. |
| `displayOrder` | Общий порядок серверов и роутеров. |

Смотрите [заполненный пример](config.example.yaml): все адреса и пароли в нём вымышленные. Для новой установки используется [пустой шаблон](../node/config.example.yaml).

<details>
<summary>Поля сервера и панели</summary>

У сервера может быть несколько панелей. Например, `awg` для AmneziaWG и `ovpn` для OpenVPN. Каждая находится внутри `connections` и имеет собственные доступы.

| Поле | Что означает |
| --- | --- |
| `type` | `wg-easy` или `openvpn-ui`. |
| `url` | Полный адрес панели, как в браузере, вместе с `http://` или `https://` и портом при необходимости. |
| `username`, `password` | Учётные данные этой панели. |
| `insecure` | При `false` сертификат проверяется; при `true` разрешается недоверенный сертификат именно этой панели. |

У самого сервера `domain` задаёт доменное имя для VPN, а `useDomain: true` включает его использование. Адреса панелей от этого не меняются. При `false` используется исходный адрес из VPN-конфига панели — он не обязательно совпадает с полем `host` в карточке сервера.

</details>

<details>
<summary>Поля роутера и связи</summary>

У роутера `endpoints` — список адресов управления. Приложение пробует их по очереди: обычно сначала домашний адрес, затем облачный. Для одного адреса также поддерживается поле `endpoint`. Логин и пароль задаются в `username` / `password`, проверка сертификата — в `insecure`.

В связи используются имена элементов из других разделов:

| Поле связи | Что указывать |
| --- | --- |
| `name` | Уникальное техническое имя связи для командной строки и API. |
| `server` | Имя сервера из `servers`. |
| `connection` | Имя подключения внутри `connections` этого сервера. |
| `router` | Имя роутера из `routers`. |
| `client` | Имя клиента в WG-Easy или OpenVPN UI. |
| `interface` | Описание VPN-интерфейса роутера. Это может быть `AntizapretAWG_EU`, а не системное имя `Wireguard0`. |
| `enabled` | `false` исключает связь из общей синхронизации и мониторинга. Если поле отсутствует, связь считается включённой. |

Выключение `enabled` не выключает VPN на роутере. Для смены подключения используйте соответствующее действие в интерфейсе.

Порядок задаётся списками `displayOrder.servers` и `displayOrder.routers`. Новые элементы, которых ещё нет в списках, добавляются в конец.

</details>

<details>
<summary>Переменные запуска для ручной настройки</summary>

| Переменная | Назначение |
| --- | --- |
| `HOST` | На каких адресах принимать подключения. Node.js по умолчанию использует `127.0.0.1`, Docker-образ — `0.0.0.0` внутри контейнера. |
| `PORT` | Порт приложения, по умолчанию 8787. Явный порт после `serve` имеет приоритет. |
| `CONFIG_PATH` | Путь к файлу настроек, если не передан `--config`. |
| `BASIC_AUTH_USER`, `BASIC_AUTH_PASS` | Логин и пароль самой AWG Sync. Обязательны для сетевого запуска. |

В схеме AZ используются `AWG_SYNC_USER` / `AWG_SYNC_PASS`: Compose передаёт их приложению как `BASIC_AUTH_USER` / `BASIC_AUTH_PASS`. `AWG_SYNC_REPO` указывает, где лежат исходники. `AWG_SYNC_DOMAIN` нужен только отдельному HTTPS-прокси из инструкции для сервера.

Файлы `.env` читает Docker Compose. Обычный запуск Node.js автоматически их не подхватывает.

</details>

## Если настройки уже были в старой версии

Старый формат с разделом `panels` поддерживается: приложение преобразует его при чтении. Простое открытие не перезаписывает файл; сохранение через интерфейс использует текущий формат.

Свой рабочий файл не заменяйте пустым шаблоном. При обновлении сохраняйте `config.yaml`, `.env` и резервные копии.

## Как перенести настройки

На старой установке скачайте зашифрованную копию через **«Конфигурация»**. На новой — откройте этот же раздел, выберите файл и введите пароль копии.

Восстановление заменит настройки приложения. Для изменения роутеров после этого нужно отдельно выполнить проверку и применение.

<details>
<summary>Права доступа и Docker</summary>

На Linux рекомендуемые права: папка настроек `0700`, файл `0600`. В Docker запись выполняет пользователь с номером 1000.

Монтируйте весь каталог `/app/config`, а не один YAML-файл. Приложению нужно создавать временный файл рядом с основным, чтобы безопасно сохранять изменения.

Пароли скрываются в штатных полях редактора, но содержатся в обычном YAML-экспорте. Не добавляйте секреты в произвольные дополнительные поля в расчёте на их автоматическое скрытие.

</details>
