# Установка вместе с AntiZapret

[← На главную](../README.md)

Эта инструкция добавляет AWG Sync к **уже работающему AntiZapret v6 на Docker Compose**. Панель будет открываться по тому же адресу, что и AZ, но на порту **8787**:

```text
https://ваш-адрес-AZ:8787
```

Например, если WG-Easy открывается по адресу `https://vpn.example.com:5443`, AWG Sync будет доступен по `https://vpn.example.com:8787`.

**Отдельный домен или второй HTTPS-прокси не нужны.** Защищённое соединение обеспечит Caddy, который уже работает в AZ.

Если AWG Sync уже установлен, для новой версии используйте раздел [«Как обновить»](#как-обновить). Повторять первую установку не нужно.

## Перед началом

Убедитесь, что панели AntiZapret уже открываются по HTTPS. Если сам AZ ещё не установлен, сначала воспользуйтесь [его официальной инструкцией](https://github.com/xtrime-ru/antizapret-vpn-docker#installation).

В примерах AZ находится в `/root/antizapret`, а AWG Sync будет лежать рядом — в `/root/awg-sync`. Подключитесь к серверу по SSH и выполняйте команды на нём. Для указанных путей нужны права root.

Если ваша папка AZ называется иначе, подставляйте её реальный путь во всех командах. Инструкция ниже относится к обычному Docker Compose, не к Docker Swarm.

## Шаг 1. Клонируйте репозиторий

Клонируйте репозиторий в отдельную папку рядом с AZ:

```bash
git clone https://github.com/RazGame/KeeneticAZSync.git /root/awg-sync
```

После этого получится две соседние папки:

```text
/root/antizapret    ваш действующий AntiZapret
/root/awg-sync      скачанное приложение
```

## Шаг 2. Подготовьте папку настроек и два файла

Перейдите в папку AZ:

```bash
cd /root/antizapret
install -d -m 700 -o 1000 -g 1000 config/awg-sync
```

Команда создаёт папку, в которую приложение будет сохранять настройки, и даёт ему право на запись.

Скопируйте два готовых шаблона:

```bash
cp /root/awg-sync/docker-compose.override.sample.yml docker-compose.awg-sync.yml
cp /root/awg-sync/deploy/antizapret.env.example .env.awg-sync
chmod 600 .env.awg-sync
```

Что это за файлы:

| Файл | Для чего нужен |
| --- | --- |
| `docker-compose.awg-sync.yml` | Добавляет приложение и его HTTPS-адрес к существующему AZ. |
| `.env.awg-sync` | Хранит путь к приложению и пароль входа в него. |

Ваши существующие `.env` и `docker-compose.override.yml` остаются на месте. Если файлы с новыми именами у вас уже есть, не копируйте поверх них шаблоны — проверьте их содержимое и используйте раздел обновления.

## Шаг 3. Задайте пароль входа

```bash
nano .env.awg-sync
```

Заполните строки:

```dotenv
AWG_SYNC_REPO=../awg-sync
AWG_SYNC_USER=admin
AWG_SYNC_PASS='ПРИДУМАЙТЕ_СВОЙ_ПАРОЛЬ'
```

Придумайте свой длинный пароль вместо текста `ПРИДУМАЙТЕ_СВОЙ_ПАРОЛЬ`. Это вход в AWG Sync; пароли VPN-панелей и роутеров вводятся отдельно.

`../awg-sync` подходит, если папки расположены как в примере. Если скачали приложение в другое место, укажите полный путь к нему, например `/opt/awg-sync`.

Сохраните файл в nano: **Ctrl+O → Enter**, затем выйдите: **Ctrl+X**.

## Шаг 4. Подготовьте команду запуска

Все следующие команды выполняйте **из папки AZ**:

```bash
cd /root/antizapret
```

Создайте недостающие служебные файлы. Уже существующие файлы эти команды не перезаписывают:

```bash
touch .env
if [ ! -f docker-compose.override.yml ]; then
    printf 'services: {}\n' > docker-compose.override.yml
fi
```

Теперь **скопируйте весь следующий блок целиком** в терминал. Он создаст сокращённую команду `azsync`, чтобы каждый раз не перечислять длинный список файлов:

```bash
azsync() {
    docker compose \
        --env-file .env \
        --env-file .env.awg-sync \
        -f docker-compose.yml \
        -f docker-compose.override.yml \
        -f docker-compose.awg-sync.yml "$@"
}
```

При успехе блок ничего не выводит. Команда `azsync` существует только в текущем окне терминала. После нового подключения по SSH перейдите в папку AZ и вставьте этот блок снова.

<details>
<summary>Если вы уже добавляли к AZ другие веб-панели</summary>

Откройте `docker-compose.awg-sync.yml`. В нём есть строка:

```yaml
PROXY_SERVICE_9: AWG Sync:8787:awg-sync.antizapret:8787
```

В стандартной установке номера 1–8 заняты встроенными панелями, поэтому используется номер 9. Если у вас номер 9 уже занят, измените его на следующий свободный. Между номерами не должно быть пропусков: Caddy прекращает чтение на первом отсутствующем номере.

Убедитесь также, что порт 8787 не используется другим приложением. Если существующие панели AZ уже работают по HTTPS, менять их домен или настройки сертификатов для AWG Sync не требуется.

</details>

## Шаг 5. Проверьте настройки и запустите

Сначала выполните:

```bash
azsync config --quiet
```

**Если команда ничего не вывела — проверка пройдена.** Если появилась ошибка, исправьте её до следующего шага. Например, сообщение про `AWG_SYNC_PASS` означает, что пароль не заполнен или файл `.env.awg-sync` не найден.

Запустите сборку и приложение:

```bash
azsync build awg-sync
azsync up -d --no-deps awg-sync
```

Затем обновите HTTPS-прокси, чтобы он подхватил новый адрес:

```bash
azsync up -d --no-deps https
azsync ps awg-sync https
```

При обновлении прокси уже открытые панели AZ могут кратковременно переподключиться. Эти команды не пересоздают VPN-контейнеры.

Дождитесь, пока AWG Sync запустится и получит статус `healthy`.

## Шаг 6. Откройте панель

В браузере на своём компьютере или телефоне откройте:

```text
https://ваш-адрес-AZ:8787
```

Войдите с логином и паролем из `.env.awg-sync`. Если по этому порту нет доступа, разрешите входящий **TCP 8787** в настройках firewall вашего хостинга и сервера.

Затем откройте **«Доступы»** и добавьте:

| Что подключаете | Какой адрес обычно указывать |
| --- | --- |
| WG-Easy / AmneziaWG из AZ | `https://ваш-адрес-AZ:5443` |
| OpenVPN UI из AZ | `https://ваш-адрес-AZ:3443` |
| Домашний роутер | Его облачный адрес KeenDNS / CrazeDNS или другой адрес, доступный с сервера. |

Если порты ваших панелей отличаются от стандартных, укажите те адреса, по которым действительно их открываете.

Далее пройдите [первую настройку](../README.md#первая-настройка). Если переносите уже настроенную AWG Sync, восстановите зашифрованную копию через **«Конфигурация»** — пересоздавать клиентов и интерфейсы не нужно.

## Как обновить

1. В панели скачайте зашифрованную копию из раздела **«Конфигурация»**.
2. Подключитесь к серверу по SSH и перейдите в `/root/antizapret`.
3. Если это новое окно терминала, снова вставьте блок с командой `azsync` из шага 4.
4. Выполните:

```bash
docker tag awg-sync:latest awg-sync:previous
git -C /root/awg-sync pull --ff-only
azsync build awg-sync
azsync up -d --no-deps awg-sync
azsync ps awg-sync
```

Первая команда сохраняет старую версию для возврата. Остальные скачивают новые файлы, собирают и перезапускают приложение. При обычном обновлении AWG Sync пересоздавать HTTPS-прокси не нужно.

**Используйте команду `azsync` и при последующей работе с этой установкой.** Обычный `docker compose up` не подхватывает дополнительный файл автоматически. При обновлении самого AZ тоже сохраняйте подключение всех трёх файлов, иначе его HTTPS-прокси может потерять маршрут AWG Sync.

<details>
<summary>Как вернуть предыдущую версию</summary>

Из папки AZ, после определения команды `azsync`:

```bash
docker tag awg-sync:previous awg-sync:latest
azsync up -d --no-deps --no-build awg-sync
```

Это возврат версии приложения. Для возврата настроек используйте резервную копию из раздела «Конфигурация».

</details>

<details>
<summary>Как добавить ссылку на AWG Sync в Dashboard AZ</summary>

Этот шаг необязательный. Выполняйте его только при уже включённом сервисе `dashboard`.

В свой дополнительный Compose-файл добавьте:

```yaml
services:
  dashboard:
    environment:
      DASHBOARD_SERVICE_6: AWG Sync:8787:awg-sync.antizapret:8787
```

Если в файле уже есть `services:`, добавьте под него только блок `dashboard`, а не второй ключ `services`. Номер 6 подходит стандартной установке с занятыми номерами 1–5. Если вы добавляли свои ссылки, выберите следующий свободный номер без пропусков.

Примените изменение:

```bash
azsync up -d --no-deps dashboard
```

Если сервиса Dashboard у вас нет, пропустите этот шаг.

</details>

## Если что-то не получилось

Из папки AZ, с определённой командой `azsync`, посмотрите сообщения:

```bash
azsync logs --tail=100 awg-sync
azsync logs --tail=100 https
```

| Что случилось | Что проверить |
| --- | --- |
| `azsync: command not found` | Вставьте блок из шага 4 заново в текущее окно терминала. |
| Не находится `.env.awg-sync` | Убедитесь, что находитесь в папке AZ, где создавали этот файл. |
| Панель не открывается на порту 8787 | Проверьте firewall и убедитесь, что выполнили `azsync up -d --no-deps https`. |
| `502 Bad Gateway` | Проверьте `azsync ps awg-sync`: приложение должно работать и быть доступно прокси. |
| `EACCES`, не сохраняются настройки | Проверьте создание папки `config/awg-sync` на шаге 2. |
| Панель открывается, роутер недоступен | Сервер должен иметь доступ к адресу управления роутером. Домашний LAN-адрес без отдельной связи с VPS не подойдёт. |
| Ошибка сертификата панели | Проверьте адрес, по которому вы открываете её в браузере. Для своего самоподписанного сертификата есть отдельное разрешение в настройках подключения. |

Настройки приложения лежат в `/root/antizapret/config/awg-sync/config.yaml`. Сохраняйте эту папку при обновлениях и не публикуйте файл: в нём находятся ваши пароли.
