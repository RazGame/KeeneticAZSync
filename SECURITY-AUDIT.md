# Проверка архитектуры и безопасности AWG Sync

Дата: 17 октября 2026 года. Основная реализация: Node.js. Проверены исходники, зависимости, конфигурация контейнера и работа через существующий HTTPS-прокси. Это проверка кода и целевых сценариев отказа, а не сертификация или полный внешний пентест.

## Что исправлено

| Область | Обнаруженная проблема | Изменение |
| --- | --- | --- |
| Вход в панель | Браузер сохранял Basic Auth в localStorage | Однократная передача при входе, непрозрачная серверная сессия в HttpOnly / SameSite=Strict cookie, Secure при HTTPS. Выход отзывает сессию, срок — 12 часов. Старое значение localStorage удаляется. |
| Сетевой запуск | Возможность открыть GUI без собственной защиты | Без авторизации разрешён только loopback. Для сетевого запуска обязательны собственные учётные данные; admin/admin запрещён. Локальный режим проверяет Host и адрес клиента против DNS rebinding. |
| API | Неограниченное тело запроса, слабая проверка формата | JSON-объект, Content-Type, предел 4 MiB; вход/выход — 4 KiB. Проверка Origin / Sec-Fetch-Site, таймауты запросов и предел соединений. Ограничены попытки входа и число сессий. |
| Пароли устройств | Редактор получал настоящие пароли панелей и роутеров | В ответах редактора маски. Сохранение маски сохраняет секрет, включая переименование сервера/роутера. Настоящие значения остаются в явном экспорте резервной копии. |
| Сохранение | Прямая перезапись могла оставить обрезанный YAML | Временный файл 0600, fsync, атомарная замена, очистка при ошибке. На Linux — дополнительный fsync каталога, где поддерживается. Новый конфиг при первом запуске также создаётся с правами 0600. |
| Параллельные изменения | Старая вкладка могла затереть новые настройки | HMAC-версия конфигурации и обязательная проверка при полном сохранении/импорте. Ответы 428 при отсутствии версии и 409 при устаревании. |
| Работа с устройствами | План мог устареть между просмотром и применением; конкурентные операции | Обязательный planToken, повторное вычисление и проверка версии перед записью. Записи сериализованы по роутеру, создание клиентов — по подключению панели. Изменение конфига блокируется во время этих операций. |
| Переключение VPN | Конфликт одинаковых адресов у разных подключений | Сохранена проверенная логика: сначала выключить другие управляемые VPN, затем настроить/включить выбранный. При сбое — попытаться восстановить прежние подключения. Ручные интерфейсы вне маппингов не переключаются. |
| Сетевой клиент | Медленный/слишком большой ответ мог удерживать ресурсы; cookies не были привязаны к origin | Абсолютный срок операции, предел ответа 16 MiB, cookies одного origin. Один повтор только безопасного GET после разрыва; POST не повторяется. |
| TLS устройств | Проверка сертификата была отключена по умолчанию | Проверка включена. Исключение допускается только явным параметром подключения; существующие явные исключения сохранены. |
| Конфиги и команды | Невалидные адреса и управляющие символы могли попасть в CLI | Проверка IP/CIDR/масок, полей команд, endpoint и параметров AWG. Ограничены дерево YAML, глубина и число узлов; запрещены циклы и опасные ключи объектов. |
| Ответы роутеров | Ошибка HTTP/RCI или частичное чтение OpenVPN могли восприниматься как успешный результат | Проверяются статус, структура и вложенные ошибки. Неудачное чтение существующего интерфейса прерывает планирование. |
| OpenVPN и ошибки | Повреждённый inline-блок мог раскрыть ключ в diff | Проверяется баланс блоков; тела блоков не включаются в diff. В желаемом профиле запрещены скриптовые хуки и отдельные опасные внешние директивы. Ошибки очищаются от известных секретных полей и ограничиваются по длине. |
| Резервные копии | Синхронный scrypt блокировал обработку запросов | Асинхронный KDF, одна выполняемая операция и очередь из четырёх. Формат v1 AES-256-GCM сохранён, размеры и пароль ограничены. |
| Веб-интерфейс | Не было ограничивающей политики скриптов и кэширования секретных API | CSP с хэшами встроенных скриптов, запретом обработчиков в HTML и frame-ancestors 'none'; no-store, nosniff, no-referrer. |
| Зависимости и контейнер | Уязвимый js-yaml; устаревшая ветка Node; лишние права контейнера | js-yaml 4.3.2, Node 24 LTS, non-root, read-only образ, cap_drop ALL, no-new-privileges, ограниченный tmpfs. Секреты и резервные файлы исключены из Docker build context. |

## Архитектура после изменений

- `security.js`: политика входа, сессии, входящие запросы, URL и защитные заголовки.
- `config-store.js`: представление конфигурации без паролей, восстановление масок и контроль версий.
- `config.js`: схема, миграция, ограниченный YAML и атомарное хранение.
- `util/http.js`: транспорт, таймауты, размеры, cookies и ограниченный повтор чтения.
- `core.js`: подготовка, вычисление плана и применение; адаптеры панелей/роутеров остаются отдельно.
- `server.js`: маршруты и координация операций. Существующее разделение проверки и применения сохранено.

Переписаны границы доверия и механизмы отказа. Полная замена транспорта, веб-фреймворка или хранилища не требовалась: она увеличила бы объём изменений без подтверждённой пользы для текущей однопользовательской установки.

## Проверки

- 60 автоматических тестов: прежние 44 и 16 новых проверок безопасности. Тесты прошли локально и в образе Node 24 с read-only rootfs, без capabilities и с тем же tmpfs, что в рабочем Compose.
- `npm audit --omit=dev`: 0 известных уязвимостей на дату проверки. Это результат для зависимостей npm, не сканирование всех пакетов ОС образа.
- Реальный YAML загружен без изменения: 3 сервера, 5 роутеров, 20 маппингов.
- Успешный вход и чтение профилей всех пяти подключений панелей: HostVDS AWG/OpenVPN, Intezio AWG/OpenVPN, IntezioDE AWG.
- Вычислены планы AWG и OpenVPN для Keenetic Giga: оба `noop`, 0 изменений. Отдельный план AWG для Netcraze Hero 5G также прошёл проверку чтением.
- Реальные профили выявили параметр AWG I1 длиной 2406 символов: лимит исправлен до 4096, добавлена регрессия. Также восстановлено чтение S3/S4.
- В этих проверках не создавались VPN-клиенты, не применялись планы и не переключались VPN.

## Особенности текущего HTTPS

В проверенной установке Caddy из AntiZapret обслуживает HTTPS на порту 8787. Сертификат проходил проверку доверия и имени сервера. Настройки TLS и маршруты других сервисов не менялись; адрес установки в публичном отчёте не приводится.

Caddy удаляет `X-Frame-Options` у проксируемых сервисов. Для AWG Sync защита от встраивания обеспечивается также CSP `frame-ancestors 'none'`. Приложение само выставляет оба заголовка; внешняя проверка учитывает поведение прокси.

## Установка на сервер

Установлен образ `awg-sync:security-20261017-225525` (также помечен `awg-sync:latest`). Контейнер `healthy`, пользователь `node`, read-only rootfs, capabilities сброшены, включён no-new-privileges. Каталог конфигурации имеет права 0700, файл — 0600. Содержимое файла до/после совпадает по SHA-256.

Внешняя проверка через действительный TLS подтвердила: анонимный запрос к конфигу — 401, вход создаёт Secure/HttpOnly/SameSite-сессию, редактор получает маски, сохранение без версии — 428, чужой Origin — 403, выход отзывает cookie. Хэши всех встроенных скриптов соответствуют CSP; запрет встраивания доходит через Caddy.

Перезапущен только сервис AWG Sync; идентификаторы остальных работающих контейнеров не изменились. В первой установочной попытке проверка ожидала X-Frame-Options, который удаляет Caddy; сработал откат. После уточнения проверки CSP повторная установка прошла успешно.

Резервные копии на сервере (доступ только root):

- исходники до аудита: `/root/awg-sync-security-20261017-225525.tar.gz`;
- предыдущий образ: `awg-sync:before-security-20261017-225525`;
- прежний Compose: `/root/antizapret/docker-compose.override.yml.before-security-20261017-225525`.

Для отката к прежнему образу требуется также вернуть прежний Compose. Новые сессии после перезапуска не сохраняются: пользователю нужно войти повторно.

## Оставшиеся ограничения

1. Приложение рассчитано на одного доверенного администратора. Нет ролей, MFA и неизменяемого журнала действий. Лимит попыток видит адрес прокси; корректные учётные данные не блокируются этим лимитом.
2. Пароли устройств хранятся на сервере в открытом YAML, необходимом для подключения. Права 0700/0600 ограничивают чтение, но не защищают от root или захвата процесса приложения. Переменные окружения Docker также доступны администраторам Docker. Для переносимых резервных копий предусмотрен зашифрованный экспорт.
3. Администратор может настраивать LAN-адреса панелей и роутеров. Валидация URL и блокировка прямого адреса метаданных не являются полноценной SSRF-изоляцией: DNS-алиасы и доступ к внутренней сети не запрещены. Для недоверенных пользователей нужны allowlist и сетевое ограничение исходящих соединений.
4. Блокировки записей находятся в памяти одного процесса. Не запускайте параллельные экземпляры или CLI с записью в те же устройства. Версии и сессии сбрасываются при рестарте; требуется повторный вход и новая проверка плана.
5. Сохранённые явные исключения TLS продолжают действовать. Для их устранения нужны доверенные сертификаты соответствующих панелей/роутеров.
6. Проверка профилей OpenVPN не является полной песочницей всех возможностей OpenVPN. Панели, из которых берутся профили, должны оставаться доверенными.
7. Пароли маскируются в штатных полях схемы. Произвольные дополнительные поля конфигурации сохраняются для совместимости; секреты в нестандартных полях не следует считать автоматически скрытыми.
8. Проверены реальные чтения выбранных роутеров и все подключения панелей, но не выполнена запись на каждую модель прошивки. Визуальная проверка браузером в этом сеансе недоступна; логика меню, порядок и CSP проверены тестами и HTTP.
